# 야르렁소리 — 생각의 연결

한국어 생각 그래프입니다. 개인 공간과 초대 링크로 접속하는 공유 방을 지원합니다. 화면은 Vite + D3, 공유 방 서버는 Netlify Functions + Blobs를 사용합니다.

## 로컬 실행

Node.js 22 이상을 사용하세요.

```sh
npm install
npm run dev -- --port 5173
```

http://localhost:5173 에서 화면과 공유 방 API가 함께 실행됩니다. 개발 서버는 방 데이터를 `.local-rooms/`에 보존합니다. 같은 네트워크의 다른 기기에서는 개발 서버가 출력한 Network 주소를 열고, 그 주소에서 만든 초대 링크를 공유하세요. `localhost` 링크는 다른 기기에서 사용할 수 없습니다.

## 공유 방 사용

1. 상단 사람 아이콘 **공유 방**에서 닉네임과 방 이름을 입력하고 **방 만들기**를 누릅니다. 공유 방은 빈 그래프로 시작하며 기존 개인 기록은 유지됩니다.
2. 같은 메뉴에서 **초대 링크 복사**를 눌러 전달합니다. 참여자는 링크를 열고 닉네임을 입력해 **참여하기**를 누릅니다.
3. 생각 추가와 연결 결과는 약 2초 간격으로 동기화됩니다. 비활성 화면은 10초 간격이며 연결 실패 시 최대 30초 간격으로 재시도합니다. 노드 위치와 확대 상태는 각 기기에서 독립적으로 계산합니다.
4. 방장에게만 생각 목록 옆 전체 삭제 버튼이 표시됩니다. 확인창에 표시된 내용 이후 방이 변경되면 삭제를 거절하고 다시 확인하도록 합니다. 삭제는 모든 참여자에게 반영됩니다.
5. 참여자는 본인의 생각만 삭제·재분석할 수 있고 방장은 모든 생각을 관리할 수 있습니다.
6. **개인 공간으로 돌아가기** 후에도 최근 참여한 방에서 다시 접속할 수 있습니다. 참여자 수는 접속 중인 인원이 아니라 방에 등록된 참여 인증 수입니다.

## 방장 인증

별도 계정 로그인 대신 서버가 256비트 무작위 인증 토큰을 발급합니다. 방 생성 시에만 방장 역할을 부여하며, 초대 링크로 참여하면 항상 참여자 역할입니다. 클라이언트에서 보낸 `role`, 작성자 ID 또는 임의 연결 데이터는 권한 결정에 사용하지 않습니다.

토큰 원문은 생성한 브라우저의 localStorage에 저장하고 서버에는 SHA-256 해시만 보관합니다. 방을 읽거나 변경할 때마다 서버에서 해당 방의 토큰을 확인합니다. 초대 링크·방 스냅샷·그래프 내보내기에는 인증 토큰과 해시가 포함되지 않습니다.

브라우저 데이터를 삭제하거나 다른 브라우저에서 접속하면 방장 권한이 자동 복구되지 않습니다. 현재는 방장 이전·계정 기반 복구를 지원하지 않습니다. 초대 링크를 가진 사람은 방에 참여할 수 있으므로 참여할 사람에게만 공유하세요.

Netlify Blobs의 강한 일관성 읽기와 ETag 조건부 쓰기로 동시 입력을 병합합니다. 전체 삭제 시 세대 번호를 증가시켜 이전 입력이나 늦게 도착한 분석 결과가 삭제한 노드를 복구하지 못하게 합니다.

## Gemini

- 개인 공간: 설정에서 개인 키를 저장합니다. 이 키는 해당 브라우저에서 Google에 직접 요청할 때만 사용합니다.
- 공유 방: 서버 환경 변수 `GEMINI_API_KEY`를 설정합니다. 브라우저에 저장한 개인 키는 공유 방으로 전송하지 않습니다. `.env.example`의 항목을 로컬 `.env`에 설정하면 개발 서버도 사용합니다. 환경 변수 변경 후 서버를 재시작하세요.
- 키가 없으면 입력 순서에 따른 임시 점선으로 연결하고 **분석 전**으로 표시합니다. 실제 의미 유사도가 아닙니다.
- 서버 키가 있으면 새 생각의 작성자가 서버 분석을 요청하고, 결과를 방 전체에 공유합니다. 실패한 생각은 작성자나 방장이 다시 분석할 수 있습니다.
- Gemini에는 새 생각과 기존 생각의 ID/라벨이 전송됩니다. 강한 연결이 없으면 반환된 가장 가까운 생각과 약한 점선으로 연결하며, 분리된 부분은 임시 연결로 이어집니다.
- 생각은 160자, 그래프당 200개, 방당 참여 인증은 100개로 제한합니다. 공유 방의 의미 분석 기준은 0.5이며 화면 설정은 각 기기의 표시 기준입니다.

## Netlify 배포

이 프로젝트에는 서버 함수가 포함됩니다. **`dist` 폴더만 드래그해서 배포하면 공유 방 API가 배포되지 않습니다.**

저장소를 Netlify에 연결해 빌드하거나 프로젝트 루트에서 Netlify CLI로 배포하세요. `netlify.toml`에 다음 항목이 설정되어 있습니다.

- 빌드 명령: `npm run build`
- 정적 파일: `dist`
- 서버 함수: `netlify/functions`
- API 경로: `/api/rooms` 및 하위 경로
- 저장소: Netlify Blobs `yarureong-rooms` (배포 환경에서 자동 인증)

공유 의미 분석이 필요하면 사이트 환경 변수에 `GEMINI_API_KEY`를 Functions 범위로 추가하고 다시 배포하세요. `VITE_` 접두어를 붙이지 마세요. 배포된 HTTPS 주소에서 방을 생성하면 다른 네트워크의 기기에서도 초대 링크로 참여할 수 있습니다.

공개 배포 및 실제 Gemini 키를 사용한 호출은 자동 테스트에 포함하지 않습니다. 폴링·저장·분석 사용량은 호스팅과 Gemini 요금제에 반영됩니다. 공개 대규모 운영에는 요청 제한과 계정 기반 방 관리가 추가로 필요합니다.

## 검증

```sh
npm test
npm run build
# 개발 서버가 실행 중일 때
node scripts/check-shared-http.mjs
```

테스트는 방장/참여자 권한, 다른 방 토큰 거절, 동시 입력, 오래된 삭제 확인, 삭제 이후 지연 응답, 로컬 서버 저장 복구와 두 개의 독립된 DOM 화면 간 전체 흐름을 확인합니다. DOM 테스트는 실제 브라우저 스크린샷 검증을 대체하지 않습니다. `npm run preview`는 정적 빌드 확인용이며 공유 API를 실행하지 않습니다.

## 주요 파일

- `src/main.js`: 그래프와 화면 이벤트
- `src/rooms-client.js`: 인증 보존, API 요청, 동기화
- `src/graph-state.js`: 빈 그래프, 목업 정리, 임시 연결
- `src/gemini.js`: 구조화 JSON 분석 요청과 검증
- `server/rooms.js`: 방 생성, 참여, 서버 권한, 노드 변경, 분석
- `server/local-store.js`: 개발용 파일 저장과 조건부 쓰기
- `netlify/functions/rooms.mjs`: Netlify Blobs 어댑터
- `vite.config.js`: 개발용 API 실행

참고: [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/generate-content/structured-output), [Netlify Blobs](https://docs.netlify.com/build/data-and-storage/netlify-blobs/), [Netlify Functions](https://docs.netlify.com/build/functions/api/).
